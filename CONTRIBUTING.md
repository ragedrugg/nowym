# Контрибьютинг

Спасибо за интерес к проекту. Коротко о том, как тут всё устроено.

## Локальный запуск

```bash
npm install
npm run dev        # tsx watch, живая перезагрузка
```

`.env` — см. `.env.example` и README (`## Как поставить`). Для голого прогона
проверок ниже реальный бот-токен не нужен.

## Перед PR

```bash
npm run typecheck  # tsc --noEmit
npm run lint        # biome check .
npm test            # node:test
```

Все три должны быть зелёными — это же гоняет CI на пуш/PR (`.github/workflows/ci.yml`).

`npm run lint:fix` чинит форматирование и часть правил автоматически.

## Стиль кода

- Форматирование и линт — [Biome](https://biomejs.dev/), конфиг в `biome.json`.
  Не спорь с форматтером, просто `lint:fix`.
- Комментарии — только там, где неочевидно *почему* (скрытое ограничение,
  воркэраунд, инвариант). Не пересказывай код в комментах.
- Явный `!` (non-null assertion) в проекте — норма там, где инвариант держит
  вызывающий код (Telegram API гарантирует поле, проверка была строкой выше
  и т.п.), поэтому правило `noNonNullAssertion` намеренно выключено в
  `biome.json`. Не значит «можно везде без разбора» — по месту думай, точно
  ли значение не будет null/undefined.
- Тесты — `node:test` + `node:assert/strict`, без фреймворков. Смотри
  `test/*.test.ts` на конвенции (имена, структура `describe`-less тестов).

## Структура

Ориентир — раздел `## Структура` в README: `src/bot` (хендлеры, диалоги,
рендер карточек), `src/services` (бизнес-логика — альбомы, кэш, поиск),
`src/storage` (Postgres), `src/yandex` (клиент Yandex Music/Ynison),
`src/infra` (rate-limit, http, логи — сквозные утилиты).

## PR

- Один PR — одна логическая правка. Не смешивай рефактор с фичей.
- Опиши *зачем*, не только *что* — код и так показывает what.
- Если правка меняет поведение (не только внутренности) — обнови README.

## Вопросы

Если что-то непонятно по архитектуре — открой issue, обсудим до того, как
писать код: дешевле поправить план, чем переписывать готовый PR.
