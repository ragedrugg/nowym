# Changelog

## 2.0.0 (2026-11-27)

### Изменено

- Бот переведён с GramIO 0.15 на yaebal 0.2.6: ядро `@yaebal/core`, меню на `@yaebal/morda` вместо `@gramio/dialogs`, long polling через `@yaebal/runner` со сторожем `getUpdates`.
- Webhook подтверждает апдейт сразу (ack-first), при остановке полученные апдейты подтверждаются, `allowed_updates` — только обрабатываемые типы.
- `npm run smoke` — запуск бота против фейкового Bot API, без Telegram и боевого токена.

### Обновление с 1.9

Зависимости `gramio` и `@gramio/*` заменены на `@yaebal/*`: после обновления выполни `npm ci` и перезапусти процесс.

## 1.9.0 (2026-11-27)

### Обновление с ≤1.8 (tsx удалён)

`tsx` больше не нужен: `.ts` запускается встроенным type stripping Node (нужен Node >= 22.19), а в `ecosystem.config.cjs` из `interpreter_args` убран `--import tsx`. pm2 не перечитывает `interpreter_args` у уже существующего процесса, поэтому `pm2 restart nowym-ts` / `pm2 resurrect` после `npm ci` уйдут в crash-loop с `ERR_MODULE_NOT_FOUND 'tsx'`. Один раз пересоздай процесс:

```bash
pm2 delete nowym-ts && pm2 start ecosystem.config.cjs && pm2 save
```

Проверка: в `pm2 describe nowym-ts | grep -i "interpreter args"` нет `--import tsx`.

## 1.8.0 (2026-11-26)

База — продовая 1.7.3 (тег `v1.7.3-prod-baseline`).

### Добавлено

- `/settings` перестроен: два раздела «трек» (качество, подпись и кнопки, способ отправки) и «карточка» (поля, прогресс, соотношение, подпись и кнопки, тумблер «карточка+трек»). Главная страница показывает все текущие значения.
- Карточка и «карточка+трек» в inline-выдаче по ссылке на трек; карточка по ссылке рисуется без линии прогресса.
- F1: настройка «Rich messages (карточка + трек)» (по умолчанию выкл.): карточка и трек одним сообщением в инлайне (первым результатом), `/np`, кнопках меню «что играет»/«карточка» и deep link `track_<id>` (не играющий трек — карточка на 0:00). Нужен Bot API >= 10.1. Если Bot API ответил на rich ошибкой, уходят отдельные карточка и трек из тех же file_id (одно предупреждение `[rich]` в логе). Если ответа не было (сеть/таймаут), исход «неизвестен»: фолбэк не запускается, чтобы не продублировать сообщение, пользователю пишется «не удалось подтвердить отправку — проверь чат». Ретрай 429, маскировка токена в логах, защита `npr:`-стэша от чужого пользователя. Выключено — поведение прежнее. Колонка `user_settings.rich_messages` добавляется аддитивно.
- Опциональный `METRICS_TOKEN`: защищает `/metrics` и детали `/health` (пусто — открыто, как раньше).
- `scripts/restore.sh` (восстановление БД из дампов backup.sh; без `--yes` только проверка) и `scripts/rollback.sh` (откат кода на копию дерева/образ `prev-<STAMP>`).
- `install.sh --yes` (без вопросов), `NOWYM_BIND_HOST`, `NOWYM_BACKUP_ENV`, `POSTGRES_SUPERUSER_PASSWORD` в `.env.example`.
- Контрактный тест на экспорты и семантику ошибок `@dvxch/yandex-music` 0.4.0; тесты watcher, Ynison, backup (stub-harness), httpServer, rich (всего 402 теста).

### Изменено

- Зависимости: `@dvxch/yandex-music` 0.2.7 -> 0.4.0; `pg` ^8.23.1, `undici` ^8.13.1, `node-wreq` ^3.2.2, `node-html-parser` ^9.0.7, `ws` ^8.23.0; `tsx` ^4.23.15 перенесён в `dependencies` (рантайм-загрузчик); `@biomejs/biome` зафиксирован на 2.6.9; `@types/node` ^26.6.10, `@types/pg` ^8.23.1, `@types/ws` ^8.18.2; `typescript` ~7.0.2; `engines.node` >=22.19; `taglib-wasm` ~1.6.1 и `@napi-rs/canvas` ~1.0.3 зафиксированы по минору. Намеренно НЕ обновлялись: gramio 0.15, ioredis 6, canvas 1.2, TypeScript 7.1, Node 24 + taglib-wasm 2.
- Lossless: `tracksFileInfo` с `raw`-транспортом (без расшифровки в памяти — меньше RAM/CPU); ответ lossy вместо lossless считается деградацией: трек отдаётся в lossy-тире, в lossless-кэш не пишется. Контейнер (ftyp/fLaC/ID3|0xFFEx) проверяется по magic-байтам перед тегированием и кэшированием; guard `isEncrypted`; короткоживущий список URL обновляется один раз; `Retry-After` ограничен потолком; число запросов ограничено; `/health`-проба lossless перебирает набор id, lossy-ответ = degraded, CDN проверяется Range-запросом с magic.
- Watcher: при терминальных ошибках Ynison (unauthorized/displaced) — экспоненциальный backoff с потолком вместо горячего цикла, принудительное обновление токена, сброс `connected` при закрытии; клиент переиспользуется через setter токена.
- Device-flow: `slow_down` увеличивает интервал опроса на 5 с (RFC 8628).
- Ynison one-shot: без ретраев на unauthorized/displaced, стабильный device id на токен (отличается от id наблюдателя), параллельные вызовы сериализуются.
- Негативный кэш лирики, wave и Genius — только для определённых «нет» (TTL 15 мин); таймаут/429/5xx/Cloudflare больше не кэшируются как «нет лирики».
- Stale-refresher: ограниченный список кандидатов-токенов, качество переносится через refresh, дедупликация батча.
- Настройки: строгий разбор числовых переменных — мусор в числе роняет старт с ошибкой, называющей переменную. Теперь падают инлайн-комментарий в целочисленной переменной (`60 # сек`) и `1e3`.
- HTTP-роуты вынесены в `src/infra/httpServer.ts`; SSE закрывается при остановке; `bot.init` с ретраями.
- Тесты изолированы от реального `.env` (`NODE_ENV=test`, `test/setup.ts`); тест-глоб в кавычках (кросс-шелл).
- Форматирование biome 2.6 (без изменения логики); `.gitattributes` (LF), расширены `.gitignore`/`.dockerignore`; CI на всех ветках с read-only токеном.

### Исправлено

- Горячий цикл watcher при завершении Ynison-сессии без исключения.
- Дубль rich-сообщения при таймауте ответа Bot API.
- `TooManyRequestsError` в клиенте Яндекса ретраится; для file-info используется голый id трека.
- `bareTrackId(null|undefined)` возвращает пустую строку.

### Безопасность

- Webhook: пустой `WEBHOOK_SECRET` в webhook-режиме закрывает вход (POST отвечают 401), бот при этом стартует; сравнение секретов fail-closed (общий `secretMatches`).
- Dockerfile: запуск не от root. docker-compose: порт 8443 на loopback (`NOWYM_BIND_HOST`), лимиты памяти, инъекционно-безопасный `docker-init.sh`.
- backup.sh: без `source .env`, токен Telegram не в argv, `flock`, `umask 077`, копия `.env` только по `NOWYM_BACKUP_ENV=1` с правами 600 и не уходит в Telegram.

### Эксплуатация

- **Требуется действие:** `POSTGRES_SUPERUSER_PASSWORD` в `.env` теперь обязателен для docker-compose (раньше суперпользователь был с паролем `postgres`). `REDIS_PASSWORD` опционален, но бот пока не умеет аутентифицироваться в Redis — оставляй пустым.
- Числовые переменные `.env` с комментарием в строке значения или в экспоненциальной записи теперь роняют старт — проверь `.env` перед деплоем.
- backup.sh: дамп проверяется `pg_restore --list` (при отсутствии `pg_restore` проверка пропускается), не прошедший — `*.dump.unverified`; ротация только после полностью успешного запуска; код возврата ненулевой при сбое дампа/проверки/отправки или параллельном запуске.
- install.sh: `npm ci`, `mktemp` для лога psql, Fernet-ключ с паддингом (как в `.env.example`), шаги с подтверждением вне терминала требуют `--yes`.
- Откат: `sudo scripts/rollback.sh <STAMP>`; данные — `scripts/restore.sh <stamp> [--db ...] [--yes]`.

### Известные ограничения и непроверенное

- Не проверено вживую: rich-путь в инлайне (`editMessageText` по `inline_message_id` с `rich_message`) и отображение на старых клиентах Telegram.
- Эффект принудительного обновления токена в watcher на практике не проверен.
- TagLib на «сыром» flac-mp4 не проверен вживую.
- Health-проба меняет ретраи общего клиента на время пробы.
- Redis в compose запускается от root через `sh -c`.
- `cardPending` — LRU на 2000 записей.
- `src/services/lyricsVideo.ts` по-прежнему закомментированная заготовка.
